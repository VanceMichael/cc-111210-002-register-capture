# 寄存器网关
`/mapping` 给出当前映射。`/read` 接受站号、区域、起始地址及字数，返回原始16位字。地址采用零基。站点1可读，站点2模拟离线。单次最多四字，6到7为禁读空洞。
第0字是组帧号，需按设备约定前后读取。`/control?change=true` 让下一次读取后切帧，`/control?mapping=next` 切换映射代号。重量由两个寄存器组成，字序与字节序分别声明；位字段共用第4字。

## 采集器遵循的约定

1. **成组一致性**：同一条作业记录涉及的测点必须来自同一帧。每组在数据段前后各读一次帧号，帧号相同才解码；中途换帧只重采该组，重采次数（`MAX_FRAME_RETRIES`，默认再试 2 次）耗尽后输出 `frame-mismatch` 质量标志，记录里只保留最后一帧原始字，不写任何数值，也不允许用旧值顶替。
2. **请求合并边界**：只有同站号、同寄存器区域、地址连续且不跨禁读空洞的测点才能合并；每个读段再按网关 `maxWords` 拆分，任何读段都不会穿越空洞或超过最大字数。
3. **映射决定一切解码**：符号、缩放、字节序、字序、位掩码全部来自映射。映射在加载时整体校验，非法映射（坏类型、重叠空洞、掩码越界、浮点缺字序声明等）直接拒绝，当前运行不受污染。
4. **热切换只在组边界生效**：新映射先暂存，当前组跑完后才切换；同一周期内旧映射完成的组保留旧版本记录，新映射的组重新规划。记录同时保存映射版本号和规范化内容摘要，版本号相同但内容变化也能识别。
5. **故障隔离**：单个站点 503 离线只把该站的组标记为 `station-offline`，其他站点与其他组继续；读异常标记 `read-error`；网关响应的映射代号与当前规划不一致时输出 `mapping-drift`，不按旧映射强行解码。
6. **停止与重启**：周期进度写入原子更新的运行日志（数据目录下 `.journal/state.json`）。优雅停止时已落盘的组保留、未开始的组不产生半成品；进程崩溃后重启会把上一周期定性为 `interrupted` 并列出未完成组，新周期对受影响的组整组重采。
7. **可追溯**：每条成组记录带 `mappingVersion`、`mappingDigest`、帧号前后值、每次尝试的原始字（`rawSegments`/`attempts`）和逐测点原始字，落盘文件带 sha256 摘要自校验。

## HTTP 接口

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/health` | GET | 服务与采集器状态 |
| `/inspect` | GET | 现场保留的单段寄存器查看，不经过成组规划 |
| `/receive` | GET | 单段查看结果留存（原回执能力） |
| `/receipts/:key` | GET | 读取单段回执 |
| `/plan` | GET | 请求规划：分组、帧前后读、拆段结果 |
| `/mapping` | GET | 当前映射、规划与暂存版本 |
| `/mapping` | POST | 提交新映射（校验失败返回 400，不影响当前映射） |
| `/mapping/refresh` | GET | 从来源拉取映射并暂存，组边界生效 |
| `/collect/once` | POST | 执行一个成组采集周期 |
| `/collect/start?interval=` | POST | 按间隔常驻采集 |
| `/collect/stop` | POST | 优雅停止，等待在途组结束 |
| `/collect/status` | GET | 运行状态、质量统计、恢复信息与日志摘要 |
| `/records` | GET | 成组记录 id 列表 |
| `/records/:id` | GET | 读取带摘要的成组记录 |

## 模块划分

- `src/mapping.mjs`：映射整体校验、内容摘要与成组请求规划。
- `src/decoder.mjs`：按映射解码原始字（uint16/int16/float32、位字段、缩放、字序/字节序）。
- `src/gateway.mjs`：网关读客户端，区分离线 503 与其他读错误，校验响应区间。
- `src/collector.mjs`：成组一致采样引擎、换帧重试、质量标志、组边界热切换、故障隔离。
- `src/journal.mjs`：原子运行日志与中断恢复。
- `src/records.mjs`：成组记录持久化与自校验。
- `src/service.mjs` / `src/main.mjs`：HTTP 接口与常驻入口，保留原单段查看命令。
